# 一、技术运行理念（够用标准）

目标：能判断可行、拆清链路、跟研发对齐——**不是自己训模型**。

## 1.1 数据 / 算法 / 算力

| 项           | 内容                                                                                                                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **入行要求** | 效果 ≈ 数据质量 × 算法适配 × 算力预算；不够就降复杂度、小模型、缓存/规则兜底                                                                                                                            |
| **产品映射** | 纠纷文本质量、规则/LLM 双引擎、云函数时延与 Key 成本                                                                                                                                                    |
| **现状**     | 规则引擎可离线演示；可选 DeepSeek/通义；失败降级 `rule_fallback`；`rt_ai_events` 记 latency/source                                                                                                      |
| **缺口**     | 产品内看不到「成本/算力取舍」；无缓存；无「为何走规则」的用户可见说明                                                                                                                                   |
| **升级方案** | ① 确认页/详情展示 `source`：大模型 / 规则 / 降级 ② 管理端指标页展示平均时延、llm 占比 ③ 同一案情 5 分钟内重复「整理」走短缓存（可选） ④ CASE_STUDY 补一小节「无 Key → 规则；有 Key → LLM；超时 → 降级」 |
| **涉及文件** | `submit.vue`、`disputeDetail.vue`、`admin/*` 新页或区块、`ai-service.js`、`CASE_STUDY.md`                                                                                                               |
| **验收**     | 演示时能指着屏幕说清三种来源；关闭 Key 仍能建档                                                                                                                                                         |
| **话术钩子** | 「预算和稳定性优先时规则兜底，效果优先时上 LLM，产品上把取舍做成可见状态。」                                                                                                                            |
| **优先级**   | **P0**（来源可见）→ **P1**（看板）→ **P2**（缓存）                                                                                                                                                      |

## 1.2 机器学习闭环

| **产品映射** | 本项目不做训练；用「规则/Prompt 迭代」模拟上线闭环：评测 → 改规则 → 再评测 → 埋点监控                                                                                                  |

| **升级方案** | ① 管理端「AI 质量」页：读 `rt_ai_events` 聚合 ② 提交时写入 `titleEdited`（AI 标题 vs 最终） ③ Badcase 标注写入 `rt_ai_badcases` ④ `EVAL.md` 增加「周跑记录表」模板（日期/准确率/改动） |

| **验收**     | 能演示：跑评测 → 改一条规则 → 再跑 → 看板有调用数据                                                                                                                                    |
| **话术钩子** | 「我们不训大模型，但闭环一样：评测集当金标，Badcase 驱动改规则/Prompt，线上用事件表监控。」                                                                                            |
| **优先级**   | **P1**                                                                                                                                                                                 |

## 1.3 知识图谱 / 结构化知识

| 项           | 内容                                                                                                                                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **入行要求** | 实体-关系；检索增强、风控、可解释问答；不替代 LLM                                                                                                                                                                                                                |
| **产品映射** | 轻量「案由类型—法律依据—步骤」关系；FAQ 检索；不做完整图数据库                                                                                                                                                                                                   |
| **现状**     | `ai-engine` RULES：category ↔ legalRefs ↔ steps；风险词升级                                                                                                                                                                                                      |
| **缺口**     | 无独立知识表；普法问答几乎不引用固定条目；不可展示「命中了哪条知识」                                                                                                                                                                                             |
| **升级方案** | ① 新增 `docs/knowledge/faq.json`（或云集合 `rt_legal_faq`）：id/标题/关键词/正文/适用类型 ② `legalChat`/`villageChat`：关键词检索 Top3 → 拼进 prompt 或直接规则拼接回答 ③ 回答 UI 展示「参考：xxx」chips ④ 可选：类型节点与 FAQ 的边（category→faqIds）写在 JSON |
| **涉及文件** | `cloudfunctions/rt-api/knowledge/` 或 `faq.json`、`ai-service.js`、`aiLegal.vue`、`assistant.vue`                                                                                                                                                                |
| **验收**     | 问「土地边界」能答出带参考条目的内容；关掉 LLM 仍能用 FAQ 答基础题                                                                                                                                                                                               |
| **话术钩子** | 「不是重型知识图谱，是场景知识表：类型—依据—步骤—FAQ，支撑可解释和检索增强。」                                                                                                                                                                                   |
| **优先级**   | **P0（下一切主攻）**                                                                                                                                                                                                                                             |

## 1.8 够用标准：端到端链路图

| 项           | 内容                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| **入行要求** | 画出 输入 → 预处理 → 检索/模型 → 后处理 → 反馈，并说失败与兜底          |
| **现状**     | CASE_STUDY 有简图                                                       |
| **升级方案** | ① 在 `PRODUCT.md` / 建档成功页用简洁步骤条展示链路 ② 下表固化为面试板书 |

```
用户口述
  → 预处理：Chip 场景、截断、敏感/暴力词检测
  → 检索：FAQ/类型知识（RAG，升级后）
  → 模型：LLM JSON 成案 或 规则成案
  → 后处理：风险抬升、拒答标记、依据列表、来源标记
  → 反馈：确认页可改 → 建档 → 事件埋点 → 干部推进
失败兜底：
  LLM 超时/无 Key → 规则
  高风险 → 升级横幅转人工
  要判决输赢 → 拒答
  检索空 → 仅通用提示 + 引导提交纠纷
```

| **优先级** | **P0**（文档+成功页一行来源） |

## 2.3 指标

| 项           | 内容                                       |
| ------------ | ------------------------------------------ |
| **入行要求** | 解决率、人工接管率、首响时延、成本、满意度 |
| **现状**     | 文档指标有；产品内不全                     |

| 入行指标   | RuralTouch 落地定义                      | 采集方式                            |

# 四、主叙事收敛（入行文末建议）

**做深唯一链路：**

`村民说事 → AI 整理成案 → 确认建档 → 干部推进 → 评测/Badcase`

| 模块                                 | 策略                             |
| ------------------------------------ | -------------------------------- |
| 议事厅 / 提交 / 记录 / 详情 / 管理端 | **主战场，优先升级**             |
| 普法 AI                              | **服务主叙事**（依据与 RAG），P0 |
| 村务助手                             | **收边界**，服务导航与本案咨询   |
| 通知 / 反馈                          | 保留，面试 10 秒带过             |
| 道德银行                             | 仅办结激励相关，不单独开 AI      |
| 团购                                 | **降权**，不升级 AI              |
