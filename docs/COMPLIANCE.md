# 商业 · 组织 · 合规叙事

> 打磨期以文档为主，不建计费系统。面试可直接引用本节。

## 1. 谁付费

| 角色           | 关系                                      |
| -------------- | ----------------------------------------- |
| 付费方（假设） | 乡镇综治 / 试点村「数字化治理」项目制采购 |
| 使用方         | 村民（说事建档）、村委调解员（推进办结）  |
| 不付费         | 村民端零付费；不靠 C 端订阅               |

**一句话：** 卖的是「调解吞吐 + 风险分流 + 可审计痕迹」，不是「村务 ChatGPT 席位」。

## 2. 谁运维

| 层级        | 职责                                                        |
| ----------- | ----------------------------------------------------------- |
| 村委管理员  | 受理/办理/办结；标 Badcase；看 AI 质量看板                  |
| 产品 / 实施 | 评测集周跑、改规则/FAQ、环境变量（LLM Key）                 |
| 基础设施    | 微信云开发（云函数 `rt-api` + 云数据库 `rt_*`），无自建机房 |

## 3. 合规红线（产品内已落地）

| 红线                   | 产品对策                                     |
| ---------------------- | -------------------------------------------- |
| 不替代法律意见         | 确认页 / 普法 / 助手固定免责；协议页可查     |
| 不预判诉讼输赢         | `refuseLegalJudgment` 拒答                   |
| 人身安全不「自行了断」 | `escalate` + 转村委 / 110 / 120              |
| 不编造条款号           | 仅法律名称级引用 + FAQ 参考 chips            |
| 数据存放               | 微信云内；作品集材料用合成案情，不上真实身份 |

## 4. 不做什么（防范围失控）

- 不开发计费 / 发票 / 多村 SaaS 租户
- 不做私有模型微调、重型向量库
- 团购 / 积分仅作辅线，面试不展开

## 5. 面试 30 秒版

> 「付费是乡镇/试点村项目制；运维是村委管理员 + 云开发；合规上我们不做法律意见替代——结构化建档、拒答输赢、高风险转人工、数据留在微信云。」
